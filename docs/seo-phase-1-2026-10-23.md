## Hallazgos confirmados

La consulta HTTP de producción, de solo lectura, confirmó:

| Origen y recurso | Respuesta observada antes del despliegue |
| --- | --- |
| `https://mymacademiadebaile.com.ar/` | 308 directo a `https://www.mymacademiadebaile.com.ar/` |
| Dominio sin www: `/clases`, `/sitemap.xml`, `/robots.txt` | 308 al mismo path con www |
| Dominio www: inicio y `/clases` | 200, canonical y `og:url` al dominio **sin www** |
| Dominio www: sitemap | 200, las 25 URLs usan el dominio **sin www** |
| Dominio www: robots | Sitemap anunciado sin www |
| `https://mymacademia-platform.vercel.app/` y `/clases` | 200, mismo canonical sin www |
| Dominio Vercel: sitemap y robots | 200, también anuncian el dominio sin www |

Se recorrieron además las 25 páginas del sitemap en el origen www, con
concurrencia limitada a tres requests: todas respondieron 200 y declararon
canonical sin www. Se confirmó que Salsa, Fitdance, Stretching y Ritmos Latinos
están actualmente publicadas, responden 200 y conservan sus slugs.

El canonical seleccionado por la aplicación apuntaba a una URL que redirige.
El código en `apps/web/src/lib/public-site/site.ts` tomaba cualquier valor de
`NEXT_PUBLIC_SITE_URL`, sin asegurar el origen oficial; cuando faltaba publicaba
`http://localhost:3000`. El valor exacto de producción no se leyó: la respuesta
HTML permite comprobar el origen incorrecto, sin acceder a secretos.

El layout público usa `SITE.url` para `metadataBase`; cada página mantiene su
canonical y `og:url` relativos. Sitemap, robots y todos los constructores JSON-LD
comparten `absoluteUrl` / `SITE.url`. Esta dependencia común explica la propagación
del problema y permite corregirlo en un punto.

El layout raíz no declaraba `noindex` para login, recuperación, administración y
portal docente. Robots limitaba rastreo, pero no era una instrucción de exclusión
de índice. Ahora las rutas privadas heredan `noindex, nofollow`; el grupo público
conserva su declaración explícita `index, follow` y los profesores de ejemplo
conservan su `noindex` individual.

## Dominio Vercel: decisión y propuesta

**No activar una redirección global del dominio Vercel en esta fase.** No hay
evidencia suficiente para garantizar su seguridad: frontend y API comparten el
host; hay cookies host-only, enlaces de recuperación, CORS de origen único,
clientes potenciales de `/api/internal/*` e instalaciones PWA docentes.
Una respuesta 308 a un POST preserva método y cuerpo, pero no transfiere cookies
host-only ni garantiza que clientes, preflight CORS o servicios externos sigan
la redirección. Los tests locales no verifican esos consumidores.

La corrección actual consolida las señales de las páginas públicas en www sin
mover endpoints ni sesiones. No usa robots como solución para duplicados.

Se deja una propuesta Vercel **inactiva** en
[`examples/seo-public-redirects.vercel.fragment.json`](examples/seo-public-redirects.vercel.fragment.json).
Después de validar dependencias y recibir autorización, se puede integrar su
array `redirects` en el `vercel.json` real, preservando `services` y `rewrites`.
El host de origen es exacto; solo contempla inicio, clases, disciplinas,
horarios, contacto y profesores; destino HTTPS www directo; `permanent: true`
usa 308. Mantiene slugs y query strings. No coincide con el destino www, apex,
previews, `/api/*`, auth, administración, portal docente ni assets.

No se recomienda reemplazarlo por un catch-all o una redirección de dominio
desde el dashboard mientras existan esas dependencias sin verificar. Con la
lista pública, los usuarios que naveguen entre hosts podrían necesitar iniciar
sesión en www; los accesos privados directos al host anterior siguen disponibles.
Un POST inesperado a una ruta pública también exige revisión antes de activar
las reglas, aunque en este repositorio las páginas públicas no tienen handlers
de ese tipo.

Referencias oficiales: [Vercel redirects](https://vercel.com/docs/redirects),
[configuración estática](https://vercel.com/docs/project-configuration/vercel-json),
[Google canonicalización](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls),
[Google sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).
